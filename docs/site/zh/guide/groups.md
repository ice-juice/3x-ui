# 分组

分组页面用于按套餐、渠道、区域、租户或内部运营规则整理客户端。它关注成员关系和组级批量操作。

## 用途

- 创建、重命名和删除分组。
- 查看每个分组的客户端数量，并识别空分组。
- 为某个分组内的全部客户端生成订阅链接。
- 按分组批量延期或调整额度。
- 增删分组成员，或删除分组内全部客户端。

## 常用操作

- 使用稳定的运营命名创建分组。
- 重命名已有分组。
- 为分组添加客户端，或移除选中成员。
- 导出该分组订阅链接。
- 重置该分组所有成员流量。
- 只删除分组标签，或删除分组内客户端。

## 主要区域

| 区域 | 含义 |
| --- | --- |
| 统计卡片 | 分组总数、已分组客户端数、空分组数。 |
| 分组名称 | 以标签形式展示的运营名称。 |
| 客户端数量 | 组级操作的影响范围。 |
| 行操作 | 订阅导出、批量调整、流量重置、成员管理、重命名和删除。 |

## 注意事项

- 删除分组和删除分组内客户端是两类完全不同的操作。
- 空分组可以作为预留标签保留，也可以在维护时清理。
- 重命名会影响现有成员的归属显示。
- 成员弹窗需要加载客户端数据，大面板上可能耗时更长。
- 分组适合做运营标签，不适合替代节点或入站归属。

## 排障提示

| 现象 | 优先检查 |
| --- | --- |
| 创建或重命名失败 | 检查是否已经存在同名分组。 |
| 导出或重置没有效果 | 确认分组内确实有成员。 |
| 成员关系看起来不对 | 回到客户端页核对客户端的 `group` 值。 |
| 批量调整数量偏少 | 某些无限期或无限流量成员可能被跳过。 |
| 删除分组后客户端仍存在 | 如果只删除了分组标签，这是正常行为。 |
